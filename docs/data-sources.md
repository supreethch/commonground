# Data sources and licences

Every source here is free to use, free to redistribute *in the ways this project
uses it*, and requires no credit card. The licences are not all the same, and
the differences change what the repository may contain — so this document is
specific about which obligation attaches to which table.

Facts marked **(verified 2026-09-06)** were checked against the live source on
that date by `scripts/verify_sources.py`, which writes
[`source-provenance.json`](source-provenance.json). Re-run it rather than
trusting this paragraph. Everything else is a design intention
until a milestone measures it.

## Summary

| Source | What we take | Licence | Redistributed here? |
| --- | --- | --- | --- |
| MusicBrainz canonical dump | artists, recordings, releases, relationships | **CC0** | No |
| MusicBrainz supplementary tables | tags, **genre associations**, ratings | **CC BY-NC-SA 3.0** | No |
| ListenBrainz listen dumps | anonymised user listening events | **CC0** | No |
| ListenBrainz web API | live listen/stats lookups | CC0 data, free, no key for public endpoints | No |
| User-supplied history exports | the user's own listening history | the user's own data | No |
| Synthetic demo users | generated interactions | MIT (ours) | Yes — generated by seeded script |
| Last.fm API | *optional* tag enrichment, off by default | free non-commercial only | No |

`data/` is git-ignored and rebuilt by `scripts/build_catalog.py`. No upstream
data ships in this repository. This mirrors the split a2transit makes between
MIT code and non-transferable transit feeds, and here it is not just tidiness —
see the ShareAlike note below.

## MusicBrainz

**Core data is CC0.** Artists, releases, recordings, release groups, works,
labels, and relationships (including URL relationships) are placed in the public
domain. This is the catalogue spine: entity identity, titles, artist credits,
release years.

**Supplementary data is CC BY-NC-SA 3.0.** MusicBrainz classifies *user-submitted
tags — including genre associations — ratings, annotations, edit history and
derived statistics* as supplementary.

This matters more than it first appears, because **genre is our primary content
feature**. Three consequences, stated plainly rather than discovered later:

1. **Non-commercial.** CommonGround is a portfolio project and stays
   non-commercial. If it ever were not, the genre features would have to be
   rebuilt from a different source.
2. **Attribution.** MusicBrainz is credited in the UI footer and in the README.
3. **ShareAlike, which is why `data/` is git-ignored.** The artist–genre matrix
   we build is a derivative of CC BY-NC-SA data. Committing it to an MIT
   repository would put a ShareAlike obligation on a directory sitting inside an
   MIT tree, which is exactly the kind of quiet licence conflict that makes a
   repository unusable by anyone else. Keeping the derived matrix out of git and
   rebuilding it locally avoids the question entirely.

**Sizes (verified 2026-09-06):** the canonical dump
`musicbrainz-canonical-dump-20260903-080002.tar.zst` is **2.2 GiB compressed**. We
do not need all of it; `build_catalog.py` filters to recordings that appear in
the sampled listen data before anything is written.

### Playback links: what MusicBrainz actually gives us

The original plan was to take legal streaming links straight from MusicBrainz
URL relationships, which are core CC0 data. **A spot check on 2026-09-06 found
this does not work well at the recording level: 1 of 10 well-known recordings
had *any* URL relation attached** (Radiohead "Creep", Billie Eilish "Bad Guy",
Dave Brubeck "Take Five", Childish Gambino "Redbone", MGMT "Kids", Kendrick
Lamar "Alright" and others all returned zero; FKA twigs "Two Weeks" returned
three `free streaming` relations).

That is a sample of ten, not a coverage measurement — but it is enough to say
the relations cannot be the *primary* route. So playback links are built the
other way round:

- **Primary:** a deterministic search URL built from artist + title. No hosted
  audio, no scraping, no API key, and it always resolves to something.
- **Opportunistic:** where a recording *does* carry `free streaming` or
  `streaming` relations, those are stored and preferred over the search link.

Real coverage gets measured during M2 ingest and recorded in
`docs/measurements.md`. **No audio is hosted by this project.**

## ListenBrainz

Anonymised listens are published as open data under **CC0**, which is what makes
real collaborative filtering possible here at all: genuine user–item
interactions with no licence encumbrance and no scraping.

**Sizes (verified 2026-09-06):** full dumps are published twice a month and
incremental dumps daily. Today's incremental,
`listenbrainz-listens-dump-2653-20260906-000002-incremental.tar.zst`, is
**370.6 MiB compressed** — one day of listens. Full dumps are substantially
larger.

We do not need a full dump. `build_catalog.py` takes a small number of
incremental dumps and samples users who have enough listens to be useful for
evaluation, producing a development slice sized to run on a laptop. The exact
slice size and the sampling rule are recorded with the built dataset so an
experiment can be reproduced.

The ListenBrainz **web API** is also free and needs no key for public endpoints;
it is used for optional live lookups, never on a request path a user waits on.

## User-supplied listening history

The Spotify-free onboarding promise means a user must be able to bring real
history without an OAuth flow. Three formats, all things a user can export
themselves:

- **Spotify GDPR data export** (`StreamingHistory*.json` / `Streaming_History_Audio*.json`) —
  this is the user requesting their own data under GDPR/CCPA, not an API call,
  and it uses none of the restricted recommendation or audio-feature endpoints.
- **ListenBrainz export** (JSON).
- **Last.fm scrobble export CSV**, as produced by the common third-party
  exporters.

Uploads are the user's own data. They are parsed, matched to catalogue entities,
stored against that user's account, and deletable. They are never redistributed
and never used to train a model that is shipped.

## Explicitly not used

- **Spotify's recommendation and audio-feature endpoints.** Restricted for new
  applications; the brief rules them out and so does the licence position.
- **Hosted audio of any kind.** We link out.
- **Scraped catalogue data.** Everything comes from a published dump or a
  documented API, within its stated rate limits, identified by a `USER_AGENT`
  carrying a real contact address — the same discipline pulse applies to its RSS
  sources.

## Last.fm — optional, off by default

Last.fm's API is free **for non-commercial use only**, asks for roughly one
request per second, caps stored data at 100 MB per integration, and requires a
"powered by AudioScrobbler" attribution.

Those terms are compatible with this project, but Last.fm is wired as an
*optional enrichment source that is off unless a key is configured*. Two reasons:
a recruiter cloning the repository should not need to register for anything, and
a required third-party key is a single point of failure in a demo. Nothing in
the core recommendation path depends on it.

## Attribution shown in the product

MusicBrainz and ListenBrainz are credited in the footer of every screen and in
the README, alongside the note that genre data is CC BY-NC-SA and this project
is non-commercial.
