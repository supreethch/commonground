# Deployment

Target: a public demo that costs nothing, needs no credit card anywhere, and can
be rebuilt from this repository. Every free-tier claim below was read from the
provider's own documentation on **2026-09-06** and should be re-checked before
milestone 6 — free tiers change, and a plan that assumes a two-year-old blog post
is how a portfolio demo ends up asking a recruiter for a payment method.

## Local

```bash
docker compose up -d          # Postgres 17 on :5434, Redis 7 on :6380
python db/migrate.py
```

Host ports are 5434 and 6380 rather than the defaults, because a2transit
(5432/6379) and pulse (5433) may already be running on the same machine.
`CG_DB_PORT` and `CG_REDIS_PORT` override them.

## Production

| Piece | Host | Why |
| --- | --- | --- |
| API (FastAPI + WebSocket) | Render, free web service | WebSockets supported; no card required |
| Database | **Neon**, free tier | 0.5 GB, scales to zero, no card |
| Frontend | Vercel, hobby | Static build, same as a2transit |
| Redis | **none** | A single instance uses the in-process broadcaster |

### Why Neon and not Render Postgres

**Render's free PostgreSQL expires 30 days after creation**, with a 14-day grace
period before deletion. A portfolio demo that dies a month after you stop looking
at it is worse than no demo, because the link stays on the résumé. Neon's free
tier has no such expiry, needs no card, and scales compute to zero when idle.

### The Render free-hour ceiling, and why this demo will cold-start

Render allows **750 free instance-hours per month per workspace**, and free
services spin down after 15 minutes without traffic (about a minute to wake).
a2transit and pulse already occupy that workspace, and pulse ships a keepalive
workflow that pings it every 10 minutes to stay awake.

One always-awake service consumes roughly 730 hours a month. **Three of them
would need about 2,190 — nearly three times the allowance.** Adding a keepalive
for CommonGround would not give it a fast demo; it would exhaust the shared
budget and suspend all three.

So CommonGround deliberately ships **no keepalive** and accepts the cold start.
The README says so in the same terms a2transit and pulse already do. This is the
correct trade: an honest one-minute wake-up costs a recruiter a minute, while a
suspended workspace costs three broken demo links.

If that becomes unacceptable, the escape hatch is moving CommonGround's API to a
different free host — Hugging Face Spaces runs FastAPI with WebSockets and no
card, on a separate quota — rather than buying hours.

### Redis is not deployed

The free tier runs one API instance, so `InProcessBroadcaster` is correct and
Redis would be infrastructure serving no purpose. `RedisBroadcaster` exists, is
tested, and runs in the compose stack, so the multi-instance path is exercised
rather than aspirational. Turning it on is an environment variable.

### Cold start and WebSockets

A spun-down service wakes on a new WebSocket connection as it would on an HTTP
request, so the first visitor's socket connects after the wake rather than
failing. The frontend still has to handle it: connection attempts back off and
retry, and the UI says the server is waking rather than showing a dead spinner.
Whether the observed wake time matches the documented "about a minute" gets
measured at M6 and recorded, not repeated from the docs.

## Secrets and configuration

Following pulse's split: `render.yaml` carries non-secret configuration and
declares secrets with `sync: false` so they are set in the dashboard and never
committed. `JWT_SECRET` is generated by the host and kept — a predictable signing
key is a complete auth bypass, and the API refuses to boot without one in
production.

## CI

GitHub Actions on every pull request:

1. `ruff check` and `ruff format --check`
2. `pytest` — engine tests, API tests, and schema tests against a Postgres
   service container
3. `vitest` and `tsc --noEmit` for the frontend
4. Playwright end-to-end against a compose stack

Worth stating plainly: **neither a2transit nor pulse runs its tests in CI.**
a2transit has 22 test files and pulse has 262 tests, and nothing checks either on
a pull request — pulse's only workflow is the keepalive ping. CommonGround has CI
from the first commit that has something to run, which is this one.
